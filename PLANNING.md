## Security / correctness

- ✅ Every gateway sub-resource mutation (beats / lanes / connections / outline items / elements) is authorized against the resource's **real** owning project — `GetResourceProject` lookup → `ResolveProjectAccess` → dispatch, 403 otherwise. No more blanket `uuid.Nil` bypass.
- ✅ JWT secret alignment, SQL-parametric everywhere, scoped CORS, admin role gate, per-user AI rate limiter, operator-allowlisted `openai_compatible` hosts, chat error UX.

## Open / deferred

- **Open-core monetization — BUILT (pending Paddle onboarding).** Decided + implemented: admin-configurable Free/Pro/Business tiers; quota enforcement (projects, collaborators-per-project, org-workspace gating); per-seat billing with auto-sync; Paddle checkout + webhooks (inert until `PADDLE_*` set); managed-AI dispatch metered by tokens with per-tier monthly allowances (Redis counters); usage display; admin subscription views; legal pages. Remaining: Paddle creds/price-ids + webhook registration + legal placeholders (done together with the operator).
- **Desktop login + sync engine — BUILT.** The Tauri build can now sign into a cloud account: token auth (the gateway returns the JWT in-body for `X-Inkwell-Client: desktop`, stored in the OS keychain and replayed as `Authorization: Bearer`; CORS/CSRF exempt token clients so the webview's `tauri://localhost` origin works). It's an *optional link* — the app still runs fully offline with no account and all data stays in local SQLite; `me()` returns the real account when linked, else the local profile, so there's never a forced login gate. Gateway defaults to `https://inkwell.garakuyard.com` with a Settings → Account override for self-hosters. **Verified end-to-end on the desktop app** (sign in / out round-trip through the webview against the live stack), plus the header reflects linked-vs-local (not-signed-in state offers "Sign in", not a fake account). Token auto-refresh shipped (`42a17e6`/`fa58e9d`): 24h access token renews silently from a 7-day refresh token in the keychain via `POST /auth/refresh`, so no daily re-login. **Sync engine — BUILT (v1, stages 1–4 + polish; see [`.orbit/docs/reference/sync-engine.md`](.orbit/docs/reference/sync-engine.md)).** Bidirectional, opt-in per project, DB-backed projects only (vault deferred), last-sync-wins, client-UUID-authoritative. Stage 1 tombstones + `updated_at` on every synced table both sides (`7dc6be0`/`c833a5c`); Stage 2 `POST /api/v1/sync/projects/{id}` gRPC `SyncProject` (apply-then-pull-excluding-pushed) verified live (`eaeaa64`); Stage 3 client engine — `local/sync.ts` full-snapshot push + apply + `sync_state`, `sync` capability, `listOwned` owner-filter fix (`845d614`); Stage 4 `SyncControl` (editor header) + `SyncRunner` (focus + 45s tick) + `useProjectSync` (`a8f9662`); "From cloud" pull (`b62171b`); polish (`b8e59e6`): dashboard card toggle, Settings → Sync section, server tombstone-GC cron (`42a17e6`). **Incremental (outbox) push — SHIPPED** (`c272ff4`): the original full-snapshot push silently lost cross-device edits (a stale device clobbered newer rows AND mis-excluded them from its own pull, so opening a stale device reverted the other's work); replaced with a `sync_outbox` that pushes only locally-changed rows — an idle device pushes nothing, so it can't clobber. **Vault file sync — SHIPPED** (`9eb56f2`; perf follow-ups `c670faa`): a separate **path-keyed** engine for vault projects (server `vault_files` table + `SyncVault` RPC; client per-file manifest diff with an mtime/size fast-path; markdown **+ binary attachments**; last-sync-wins; fresh-device folder-pick; oversized-file skips surfaced in the UI). **Two-device app-level verification — DONE 2026-07-16**, driven through two live Tauri webviews against the local stack, and it earned its keep. The **row engine passed** (fresh-device pull, both edit directions, tombstones, and the stale-device no-clobber case that motivated the outbox rewrite). The **vault engine failed**: `stat`/`readFile`/`writeFile` were never granted in the Tauri capability manifest, every call site swallowed the denial, and so every file silently dropped out of every push behind a green "Synced" — **broken since the engine's first commit**, and invisible to the server-side curl verification because curl never runs the client. Fixed (`61e233a`), the silent swallow fixed too (`27c32d7`), guarded by a capability test, and re-verified byte-for-byte incl. binary attachments + deletes. **Remaining:** one human click through the native vault folder picker (Orbit #116) — WebDriver automation maps no X window, so the GTK dialog can't be driven; `vault_path` was seeded exactly as `pullProject` writes it. Still deferred: "remove from cloud" semantics.
- **Google Drive backup (Settings → Integrations "#16") — SHIPPED 2026-09-15.** Full design in [`.orbit/docs/log/2026-06-22-drive-backup-design.md`](.orbit/docs/log/2026-06-22-drive-backup-design.md). Desktop users connect their own Google account through installed-app OAuth/PKCE with the narrow `drive.file` scope, explicitly select local projects, and manually back them up. Vaults preserve their real folder tree and binary attachments; every other editor produces a lossless `.iw` (format v2 includes board drawings) plus a readable PDF, with screenplay-specific formatting. SHA-256 mappings skip unchanged data and update Drive files in place; missing/trashed files and folders are recreated, runs expose progress/errors/last-success, and users can stop between uploads. Refresh tokens stay in the OS keychain; access tokens are memory-cached and cleared on disconnect. Operator credentials are compile-time inputs from an ignored `.env.drive.local` in development. Live-verified against a real Drive account for both vault and non-vault paths, including PDF inspection.
- **Mobile (Android/iOS)** — Tauri v2 targets mobile, so it's mechanically possible, but a *large* vertical for this app: the vault's arbitrary-folder filesystem model + recursive watcher, the OS keychain (BYO keys), the desktop window chrome, and the keyboard-centric editor UX don't map to mobile sandboxing/touch. Cleanest path is a hosted-first thin client (remote storage), which is gated behind the desktop-login/sync work above. Revisit AFTER desktop login + sync.
